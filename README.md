# CARA v4.2: Digital Twin Cockpit (frontend prototype)

A React + Vite + Tailwind CSS implementation of the CARA v4.2 "Digital Twin Cockpit" interface, converted from a
Google Stitch design export.

## Status: what this is and is not

This repository currently contains **only a frontend prototype**. Use these four terms when describing it:

| Term | Meaning here |
|---|---|
| **Simulated** | Behaviour generated by frontend logic in the browser, without a connected real-world system. Example: the Decision Engine screen applies the documented decision rules to what-if inputs. |
| **Illustrative** | Sample values or visuals that are not experimental results. Example: component health values, driver metrics, and every chart. |
| **Planned** | Functionality intended for future implementation: a FastAPI backend, XGBoost vehicle-health estimation, a Random Forest driver-state model, a conversational layer, explainability, and cockpit interventions. |
| **Not implemented** | Functionality that does not currently exist, including the Recommendations, Journey Insights, Conversation Assistant and Settings screens (placeholders). |

Nothing in this prototype is a trained model prediction, real-time inference, live telemetry, a validated result or an
experimental finding. There is no backend, no ML model and no network data source; all data is hardcoded in
`frontend/src/data/`. The app shows a short prototype notice at the end of every page.

### What the simulation is based on

The Decision Engine screen is a **frontend simulation of the specification in the research draft** (latest conference
version), not an implementation of a validated system:

- **Decision rules:** Table II of the draft, used exactly as written and in the same priority order (Emergency Alert,
  Take Rest, Slow Down, Vehicle Service, Safe Driving). The draft states that its thresholds are design choices that
  have not been validated against real driving. See `frontend/src/utils/decisionRules.js`.
- **Vehicle Health Score:** `VHS = 0.25 battery + 0.30 brakes + 0.25 engine + 0.20 tires` (Eq. 1). These weights are
  specified in the paper. The component values are illustrative samples in `frontend/src/data/vehicleHealth.js`.
- **Environmental Risk Score:** `ERS = 0.30 W + 0.25 T + 0.25 R + 0.20 V` (Eq. 2), with the paper's scores: weather
  Clear 0 / Rain 45 / Fog 65 / Storm 90, road Dry 0 / Wet 40 / Icy 90, `T = 100 x traffic density` (density 0-1) and
  `V = 100 (1 - v/10)` for visibility `v` km clipped to 0-10. The paper states that the ERS weights are design choices
  (nothing is trained). Every scenario's ERS, including the Decision Engine's "Icy Storm" (Storm, Icy road, density 0.80,
  2 km = 85.5), is computed by the same function from the inputs shown on screen; there is no hard-coded or overridden
  score. See `frontend/src/data/environmentPresets.js`.
- **Prototype interpretations (not paper-defined):** the paper defines only the weather categories Clear / Rain / Fog /
  Storm and the road categories Dry / Wet / Icy. The scenario names on screen (Light Drizzle, Heavy Rain, Dense Fog,
  Torrential, Icy Storm ...) are mapped to those categories by hand: Light Drizzle = Rain + Wet, Heavy Rain = Storm + Wet,
  Dense Fog = Fog + Wet, Clear Daylight = Clear + Dry. The screens say so. The sample visibilities are kept inside the
  paper's Table III ranges for the mapped category.
- **Not ERS inputs:** temperature, humidity, friction, precipitation rate, water-film depth, aquaplaning risk and corridor
  speed are illustrative display values and take no part in the ERS.
- **Rounding:** rules compare the unrounded VHS and ERS to the thresholds; values are rounded to one decimal for display
  only (a floating-point tolerance of 1e-9 is applied, nothing more).
- **Illustrative composite:** the "risk" figure (driver 0.40, environment 0.35, vehicle 0.25) comes from the Stitch
  design. Its weights are placeholders: not calibrated, not part of the research methodology, and not used to select the
  recommendation.

Driver state and the environment scenario are shared across the top bar, Overview and their own screens. The Decision
Engine sandbox deliberately keeps its own independent what-if inputs.

## Running the frontend

Requires Node.js 18, 20 or 22+ (the range supported by the current Vite 5). Developed and tested with Node 26.

```bash
cd frontend
npm install          # or `npm ci` to install exactly what package-lock.json specifies
npm run dev          # development server (http://localhost:5173)
npm run build        # production build into frontend/dist/
npm run preview      # serve the production build locally
node tests/run-unit.mjs   # unit tests: Table II rules, VHS / ERS formulas, boundaries (no extra dependency)
```

The Tailwind and PostCSS configuration is anchored to the files in `frontend/`, so builds also work when started from
another directory, for example `npm --prefix frontend run build` from the repository root.

## Screens

Overview, Vehicle Twin, Driver Twin, Environment Twin and Decision Engine are implemented from the Google Stitch design export (which is not included in this repository).
Recommendations, Journey Insights, Conversation Assistant and Settings are placeholders marked "Not implemented": no
design was exported for them. Unknown URLs show a Not Found page.

## Accessibility

- A "Skip to main content" link, a single `h1` per screen, labelled landmarks and labelled controls.
- Visible keyboard focus ring; all interactive elements are real buttons and links (including the vehicle hotspots).
- The mobile navigation drawer closes with Escape, moves and restores focus, and is removed from the tab order when closed.
- Decorative icon glyphs are hidden from screen readers.
- `prefers-reduced-motion` disables animations and transitions.
- Text contrast was checked against WCAG 2 AA (4.5:1, or 3:1 for large text) over the composited background colours.

Not covered: a full screen-reader walkthrough, and testing in browsers other than Chromium.

## Deployment notes

The production build is a static single-page application (`frontend/dist/`). No hosting platform has been chosen, so no
provider-specific configuration is included. What any host must provide:

- **SPA fallback (required).** Routing happens in the browser (React Router, `BrowserRouter`). The host must serve
  `index.html` for every path that is not a file, otherwise opening or refreshing `/vehicle-twin`, `/decision-engine` and
  the other routes returns a 404 from the server. With the fallback in place, unknown URLs render the in-app Not Found
  page but the HTTP status is 200 (a "soft 404").
- **Site root.** The app assumes it is served from `/` (Vite `base: '/'`, no router `basename`). Serving it from a sub-path
  requires setting Vite's `base` and the router's `basename`.
- **No environment variables or secrets.** The build needs none, the source contains no API keys, backend URLs or
  `localhost` references, and the app makes no network calls of its own.
- **External resources: none.** Fonts (Geist, Space Grotesk, Material Symbols) and every illustration are served from the
  application itself, so the page makes no request to Google or any other third party. A strict Content-Security-Policy
  can use `default-src 'self'`, plus `img-src 'self' data:` (the small avatar SVG is inlined by the build) and
  `style-src 'self' 'unsafe-inline'` (the React app sets inline styles). The Material Symbols font file is about 1.1 MB
  (the same file Google served); subsetting it to the icons actually used is a possible later optimisation.
- **Caching.** Built asset file names contain a content hash and can be cached for a long time; `index.html` should be
  revalidated.
- **Browser support.** Modern evergreen browsers. The app uses the `inert` attribute (Chrome 102+, Safari 15.5+, Firefox
  112+), `:focus-visible` and `backdrop-filter`. It has been tested only in Chromium.

## Design reference

The interface was converted from a Google Stitch export (`cara_v4.2_digital_twin_cockpit.html`), which was the visual
source of truth for the layout and styling. **That original export is preserved unchanged on the author's machine but is
intentionally not published in this repository**: it contains personal sample data, links to third-party images whose
licences are not established, and runtime scripts loaded from CDNs. The on-screen wording and the Decision Engine rules
in this repository intentionally differ from it where the export made claims the prototype cannot support.

## Known advisories

`npm audit` currently reports advisories in `react-router-dom` 6.x (open redirect via backslash; server-rendering
deserialisation) and in the Vite 5 / esbuild development server. The router issues are not reachable in this app: it
has no server-side rendering and its links are static. They are documented here and will be addressed in a dedicated,
tested upgrade step. Vite 6.4.x is the planned fix for the development-server advisories.
